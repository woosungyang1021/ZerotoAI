# 선 넘은 PM 단속반

공유 PM(전동킥보드)이 지정 주차구역에 제대로 반납됐는지 엣지 AI가 판정하고,
그 결과를 현장 시연 영상과 함께 웹에서 확인하는 프로젝트입니다.

**데모:** https://woosungyang1021.github.io/ZerotoAI/

## 판정 방식

기체의 접지점(바퀴가 땅에 닿는 지점)을 IPM 호모그래피로 지면 좌표(BEV)로 옮긴 뒤,
그 발자국이 허용 구역과 얼마나 겹치는지로 판단합니다.

| 판정 | 조건 | 기록 |
|------|------|------|
| 반납 승인 | 발자국이 구역과 70% 이상 겹치고 기체가 서 있음 | `RETURN_VALID` |
| 구역 이탈 | 겹침 70% 미만 (경계선에 걸친 경우 포함) | `INVALID_OUT_OF_ZONE` |
| 전도 | 구역 안이어도 기체 축이 누움 | `INVALID_FALLEN` |
| 판정 보류 | 정지 여부 확인 중 — 확정 판정이 아니라 로그에 남지 않음 | `PENDING` |

- 검출/세그먼트: YOLO26m-seg (배포본 — s 모델은 야간 비교용으로만 씀)
- 디바이스: Jetson Orin Nano (현장 추론 초당 2~3회)
- 판정 기록: 7개 세션 49건 (위반 21 / 정상 28)

## 시연 케이스 11편

상황을 하나씩 만들어 찍은 현장 영상입니다. 영상에는 판정 오버레이가 이미 입혀져 있습니다.

### 주차 판정 (주간, 7편)

| 케이스 | 세션 | 결과 |
|--------|------|------|
| 정상 대여 · 정상 반납 | 5 | 반납 승인 |
| 경계선에 걸쳐 반납 | 6 | 반납 거부 (겹침 55.8%) |
| 구역 밖에 반납 | 6 | 반납 거부 (겹침 0%) |
| 구역 안이지만 넘어짐 | 6 | 반납 거부 (전도) |
| 넘어짐 · 판정 보류 | 6 | 반납 보류 |
| 지쿠 · 끌고 와서 정상 반납 | 7 | 반납 승인 |
| 지쿠 · 타고 와서 정상 반납 | 7 | 반납 승인 |

### 야간 인식 (4편)

판정 로그가 없는 촬영분입니다. 모델·조명에 따라 야간 인식이 어떻게 달라지는지 보여줍니다.

| 케이스 | 내용 | 인식 결과 |
|--------|------|-----------|
| 야간 반납 판정 | 가로등만 있는 야간 반납 | 승인 확정 (85프레임 검출) |
| m 모델 · 야간 인식 | 아래와 동일 조건, m 모델 | 913프레임 중 80% 에서 검출 |
| s 모델 · 야간 인식 | 동일 조건, 더 가벼운 s 모델 | **356프레임 전부 0대** |
| 조명 유무에 따른 차이 | 조명 꺼짐 → 켜짐 | 조명 있을 때만 검출 |

### 영상과 판정을 맞춘 방법

영상 좌상단에는 마지막 판정이 `17:28:26  #37 SWING  INVALID_OUT_OF_ZONE` 형태로 찍혀 있습니다.
이 배너가 바뀌는 프레임을 찾아 `judgments.jsonl` 의 (시각, track_id)와 대조하면
영상 몇 초 지점이 어느 판정인지 정확히 떨어집니다. `make_cases.py` 의 `ANCHORS` 표가 그 결과입니다.

영상은 파이프라인 출력을 고정 fps로 인코딩한 것이라 영상 시간과 실제 시계가
완전한 정비례는 아닙니다(90초에 약 3초). 그래서 비례식 대신 확인된 프레임을 그대로 씁니다.

### 영상에 보이는 기체를 모두 맵에 올린 방법

젯슨은 **확정 판정만** 로그에 남깁니다. 지나가는 중이거나 멈춤을 확인하는 중(PENDING)인
기체는 기록이 없습니다. 대신 영상에는 그 기체들도 박스가 그려져 있어, 거기서 직접 읽어냅니다.

1. 박스 색으로 상태를 구분합니다 — 초록 = 승인, 주황 = 거부, 흰색 = 보류
2. 겹쳐 뭉친 박스는 열마다 최하단 화소를 훑어 밑변 단위로 끊습니다
3. 같은 색 글자를 걸러내려고 양 끝에 세로변이 있는지 확인합니다
4. 밑변 가운데(접지점)를 `judge_calib.json` 의 호모그래피로 지면 좌표로 옮깁니다

호모그래피는 캘리브레이션 4점에서 오차 0.001m 이내로 복원됩니다.
프레임당 3~5대가 잡히며, 박스가 심하게 겹치면 한두 대를 놓칠 수 있습니다.

야간 영상은 조건이 달라 `extract_live.py` 의 `PROFILE` 에서 따로 잡습니다. 박스 색이
어두워 채도·명도 하한을 낮추고, 화면 아래 돌난간이 흰 박스로 오인돼 허용 좌표를 구역
근처로 좁혔습니다. **흰색(보류) 박스는 야간에 정밀도가 50% 수준이라 아예 제외**하고
확실한 초록·주황만 씁니다. 그래서 야간 맵에 보류 기체는 뜨지 않습니다.

## 구성

```
docs/index.html    판정 리포트 웹페이지 (GitHub Pages 공개 대상)
docs/cases.json    케이스 메타 + 판정 이벤트
docs/media/        웹용으로 줄인 시연 영상 11편 + 대표 장면 (총 26MB)
docs/live/         영상에서 뽑아낸 프레임별 인식 기체 좌표 (총 90KB)
추가/              야간 원본 영상 (avi, 375MB — 커밋하지 않음)
make_cases.py      judgments.jsonl + 원본 영상 → docs/ 데이터 생성
extract_live.py    영상 오버레이 → 프레임별 기체 좌표 추출
make_results.py    원본 추론 결과 생성
replay_server.py   로컬 확인용 간이 서버
judgments.jsonl    젯슨이 남긴 판정 로그 (원본, 49건)
judge_calib.json   주차구역 폴리곤 캘리브레이션
```

원본 영상(주간 1080p 179MB, 야간 avi 375MB)은 저장소에 넣지 않습니다. `docs/media/` 의
압축본만 커밋합니다. 야간 영상은 센서 노이즈 때문에 그대로 인코딩하면 157MB가 되어,
노이즈 제거(hqdn3d)를 강하게 걸고 800px 로 줄여 10.5MB 로 만들었습니다.

## 데이터 다시 만들기

```bash
python make_cases.py            # 판정 데이터만
python make_cases.py --video          # 원본 영상 재인코딩까지
python make_cases.py --video night    # 야간 4편만
python extract_live.py night          # 야간 4편만 좌표 추출
python extract_live.py          # 영상에서 프레임별 기체 좌표 추출 (원본 mp4 필요)
```

## 로컬에서 보기

`fetch` 를 쓰기 때문에 파일을 더블클릭하면 열리지 않습니다. 서버로 띄우세요.

```bash
python -m http.server 8000 --directory docs
```

단, 파이썬 기본 서버는 Range 요청을 지원하지 않아 영상 탐색(seek)이 막힙니다.
GitHub Pages에서는 정상 동작합니다.
